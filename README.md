# Online Retail — Python + SQL + Streamlit

Разбор датасета **Online Retail II** (UCI).  
https://archive.ics.uci.edu/dataset/502/online+retail+ii
Один xlsx, ~525k строк, зерно — позиция в чеке.


**Дашборд:** [https://cronline-retai-maincat.streamlit.app/]

## Зачем делал

Хотел пройти тот же цикл, что на собесах: понять зерно → почистить → посчитать KPI → когорты / RFM.  
Сначала pandas, потом те же цифры в MySQL. 

Отдельно от Olist(+его первым делать - ошибка, скоро к нему вернусь и доведу до ума): там много таблиц и repeat ~3%. Здесь один файл, но repeat нормальный (~67%), можно рахобрать когорты.

## Результаты анализа 

### Качество

Сначала зафиксировал зерно: одна строка — позиция в чеке, не заказ. На одном Invoice может быть 10–20 строк, поэтому COUNT(*) для заказов не катит — только COUNT(DISTINCT Invoice).

В raw нашёл отмены (инвойсы с C в начале) и строки с нулевым/отрицательным qty или price. После фильтров осталось ~511k строк и ~28.8k заказов. Sanity: GMV ~£10.3M, даты с дек 2009 по дек 2010.

Около 20% строк без Customer ID — анонимные покупки. Для repeat, когорт и RFM брал только клиентов с id (~4.3k человек).

### Продажи

Почти вся выручка — United Kingdom (~93%). AOV по UK ~£460. В Европе чек выше, но заказов мало.



### Динамика

Пик — ноябрь 2010 (1.47M GMV). Осенью 2010 виден рост к лету.  
Декабрь 2010 выглядит как обвал (−70% к ноябрю) — это обрезанный месяц в конце выборки. 2009 год в годовой разбивке сравнивать бессмысленно: там только декабрь.

### Повторные покупки и когорты

Repeat rate ~**67%** — т.е. 2/3 клиентов с id покупали больше одного раза. Для e-commerce это много (в Olist на тех же метриках было ~3%).

Когорты считал по месяцу первого заказа. У стабильных когорт (2010-04 — 2010-07) месячный retention на 2-й месяц жизни — порядка **15–25%**. Когорта **2009-12** завышена на ранних месяцах: данные начинаются с декабря, часть «новичков» на самом деле старые клиенты.

Всё пересчитал в SQL (PERIOD_DIFF, VIEW customer_orders) — цифры совпали с pandas.

### RFM

Разбил клиентов на сегменты по давности, частоте и сумме (квантили в pandas, NTILE в SQL).

| Сегмент | Клиентов | Средний GMV |
|---------|----------|-------------|
| Потерянные | ~1 015 | ~£404 |
| Лояльные | ~973 | ~£1 351 |
| Чемпионы | ~926 | ~£6 188 |
| Под риском | ~688 | ~£1 515 |
| Новички | ~367 | ~£503 |

«Чемпионы» — недавно покупали, часто, много тратят. «Потерянных» больше по числу, но денег с них мало. Есть один выброс по GMV (349k на клиента).

### Дашборд

На Streamlit вынес обзор (GMV, AOV, фильтр по стране/году), продажи по месяцам, heatmap когорт и RFM-сегменты. Данные из parquet, без пересчёта на лету из xlsx.

## Pipeline

```text
data/online_retail_II.xlsx
        │
        ├─► scripts/grain_key.py      профиль, clean, метрики → data/clean.parquet
        ├─► scripts/cohort_rfm.py     когорты + RFM → data/customers.parquet
        ├─► scripts/load_retail.py    заливка в MySQL
        ├─► sql/online_retail.sql     те же шаги в SQL (VIEW, retention, RFM)
        └─► app.py                    Streamlit дашборд
```

| Файл | Что делает |
|---|---|
| scripts/grain_key.py | загрузка xlsx, clean, sanity, GMV / MoM / repeat |
| scripts/cohort_rfm.py | retention-матрица, RFM-сегменты |
| scripts/load_retail.py | xlsx → таблица orders в MySQL |
| sql/online_retail.sql | VIEW clean_orders, people_orders, когорты, customer_rfm |
| app.py | дашборд: обзор, продажи, когорты, RFM |

Код и sql в репо.
